# Future V2V 自适应匹配时机研究方案

## 研究定位

本项目研究未来车车互助充电平台中的动态批量匹配问题。平台不是每个时刻都立即派单，而是在订单等待、车辆供给、电量约束、取消风险和空间压力之间权衡，决定当前是继续等待形成更好的批次，还是立即触发匹配。

主环境使用 TLC Manhattan 黄出租数据进行需求校准。出租车数据提供真实城市时空需求、OD 热点、行程时间和价格强度；V2V 专属属性仍由业务模型生成，避免把网约车/出租车业务直接等同于 V2V 互助充电。

核心范式是：

```text
强化学习决定何时匹配
运筹优化决定如何匹配
```

这样可以避免端到端直接输出大规模匹配边导致动作空间过大，也能保留组合优化在可行性约束和全局匹配上的稳定性。

## 问题定义

每个决策 tick，平台观察低维聚合状态：

- 活跃订单数量、总需求电量、平均等待比例、临近截止订单数。
- 可用车辆数量、总可供电量、平均剩余在线时间、fleet 占比。
- 供需压力、热点压力、可行边密度、候选边利润统计。

动作空间为二元：

```text
0 = WAIT
1 = MATCH
```

当选择 `WAIT` 时，系统推进一个 tick，订单可能继续等待、取消或过期。  
当选择 `MATCH` 时，平台调用约束匹配器，在当前订单和车辆之间求解最大期望利润匹配。

## 算法路线

第一版采用 Double DQN 学习匹配时机。DQN 不直接选择具体订单-车辆边，只学习触发匹配的时机。匹配结果由约束二分图匹配器产生。

训练包含 teacher replay prefill，但 teacher 只输出同一动作空间下的 `WAIT/MATCH`，不输出匹配边，避免模仿学习接口和 RL 控制接口不一致。

默认 teacher 包括：

- 截止期触发。
- 供需压力触发。
- 短视 lookahead timing。

## 研究价值

V2V 和网约车派单不同，订单不是“人等车”，而是“能量需求等待移动供给”。除空间距离外，还存在需求电量、可供电量、保留电量、车主时间窗口、愿付价和报价等约束。动态匹配时机能体现 V2V 的关键难点：等待可能形成更优批次，但也可能导致取消、过期和车辆离池。

## 默认对比基线

- 每 tick 固定匹配。
- 每 2 tick 固定匹配。
- 每 3 tick 固定匹配。
- 队列长度阈值匹配。
- 截止期触发匹配。
- 供需压力触发匹配。
- 短视 lookahead timing。

主比较对象不是某个强规则的边级得分，而是不同匹配时机策略在同一仿真器和同一匹配器下的约束利润表现。
